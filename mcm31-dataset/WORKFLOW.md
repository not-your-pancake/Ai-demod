Read this once. It answers: what happens to the files I already have, where do
new ones go, and what changes when I move to a new board.

---

| Question | Answer |
|---|---|
| The 7 B1 files I already captured? | **Leave them alone.** Verified and finished. Never move, rename or overwrite them. |

## 4. The naming rule — this is what the code reads

```
<board>_<modulation>_<tag>.CSV
```

- `<board>` — `B1` … `B8`
- `<modulation>` — `BPSK`, `QPSK`, `8QAM`
- `<tag>` — either an **attenuation** (`A0`, `AMID`, `AMAX`) → Block 1
  or a **pattern name** (`T2`…`T6`, `Q2`, `Q3`, `S1`) → Block 2

The code decides everything from this. Get the name right and nothing else
needs configuring. Get it wrong and the file is checked against the wrong
pattern and will fail for no reason.

Use CAPITAL `.CSV`, and keep the exact spellings above.

## 5. What each file is actually for

| Files | How many | Role in the paper |
|---|---|---|
| `*_A0` | 3 per board, 24 total | Cleanest signal. Main training data. |
| `*_AMID`, `*_AMAX` | 4 per board, 32 total | **Leave-one-attenuation-out** split, and locating each board's lock cliff. |
| B1 Block 2 words | 8, B1 only | **Leave-one-pattern-out** — the memorisation test. This is the primary evaluation. |
| B2 … B8 | 49 | **Leave-one-board-out** — cross-device generalisation, 8 folds. |

Block 2 lives on B1 only because it tests the *model*, not the *board*. Running
it on all 8 boards would cost 4 more hours and add nothing.

## 6. Routine for a new board (B2 … B8) — about 45 minutes each

1. **Photograph the panel as-found**, before touching anything.
   Save as `photos/B2_panel_asfound.jpg`.
2. **Match every switch to B1's reference photos.** Do not turn the PHASE
   trimmer. Do not turn the noise knob — it stays fully counter-clockwise.
3. **Run the START test** (Part E of `BENCH_CARD_B1.md`). 30 seconds. Mandatory
   on every board.
4. **Photograph the panel as-set**, `photos/B2_panel_asset.jpg`.
5. **Capture the 7 files** in the order in `BENCH_CARD_B1.md` Part F.
   - press **START** after every switch change
   - **re-range CH1** after every modulation change *and* every attenuation change
   - CH1 must look **messy**, never a clean smooth sine
6. **Run `benchcheck.py` on each file before moving to the next one.**
7. Fill in the logbook rows at the bench.
8. When all 7 say GOOD, run the full verification:

```powershell
& "E:\Ai demod\.venv\Scripts\python.exe" "E:\Ai demod\mcm31-dataset\src\verify.py" "E:\Ai demod\mcm31-dataset\raw\B2"
```

9. Message me with the result before starting the next board.

## 8. What the folder-level check can and cannot catch

`verify.py` runs three different stale-word tests, and they cover different cases:

| Check | Catches | Works when |
|---|---|---|
| **9** — same word must match itself | START not pressed between two captures of the same word | a pattern was captured **more than once** (Block 1) |
| **9b** — fingerprint | wrong word loaded, or no data at all | always |
| **9c** — different words must NOT match | START not pressed between two **different** words | a modulation has **two or more different words** (Block 2) |

Check 9c matters specifically for Block 2. Every held-out word is captured only
once, so check 9 cannot help, and check 9b cannot either — T1…T6 all share the
fingerprint `[1,1,1,1,1,1,1,1]` by design. Only 9c would notice a stale word
there.

---

## 9. Do not

- Do not rename or move files after they pass. Templates and reports are keyed
  on the filename.
- Do not delete `raw/` files, ever. Everything else can be regenerated.
- Do not re-capture a file that already passed. There is no benefit and it
  risks replacing a good file with a bad one, which has already happened twice.
- Do not adjust the PHASE trimmer or the noise knob on any board.
